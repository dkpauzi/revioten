## 2. Cara mengulang dari nol (Windows)

Langkah ini untuk komputer pemilik (Windows). Bukti M0.1 di sesi ini dibuat di container cloud Linux, jadi langkah Windows di bawah belum dicoba di komputer Anda. Bila ada langkah yang gagal, catat pesan errornya untuk sesi berikutnya.

### 2.1 Pasang alat

1. **Git for Windows.** Unduh dari https://git-scm.com/download/win. Versi terbaru saat dicek: v2.56.0.windows.4.
2. **Go 1.27.3.** Buka https://go.dev/dl/, lalu pilih installer Windows (`.msi`) untuk go1.27.3 sesuai prosesor Anda (biasanya amd64 atau x86-64).
3. **Node.js 24.22.1 LTS.** Unduh `node-v24.22.1-x64.msi` dari https://nodejs.org/dist/v24.22.1/. Sebelum memasang, cocokkan sidik jarinya di PowerShell:
   ```powershell
   Get-FileHash .\node-v24.22.1-x64.msi -Algorithm SHA256
   ```
   Hasilnya harus sama dengan baris di `SHASUMS256.txt` di folder yang sama. Saat dicek di cloud, nilainya `3bda4baf1ee709b33cf920dd633106ddb23951e322bff9c03ec9f64ab8981b01`.
4. **Docker Desktop untuk Windows.** Unduh dari https://www.docker.com/products/docker-desktop/. Docker Desktop di Windows memakai WSL 2. Bila WSL belum ada, jalankan `wsl --install` di PowerShell sebagai Administrator, lalu restart. Virtualisasi juga harus aktif di BIOS.
   - **Perhatikan lisensi (belum diverifikasi):** setahu saya, Docker Desktop gratis untuk penggunaan pribadi dan usaha kecil, sedangkan perusahaan besar butuh langganan berbayar. Halaman docs.docker.com tidak bisa saya buka dari cloud, jadi syarat terbarunya belum saya cek. Ini bukan nasihat hukum. Bila laptopnya milik perusahaan, tanyakan juga izin IT untuk memasang Docker.
   - **Alternatif (usulan):** Docker Engine yang dipasang di dalam distro Linux WSL 2, tanpa Docker Desktop. Perintah `docker compose` di catatan ini tetap sama.
5. **Editor (opsional).** VS Code dengan ekstensi Go dan Svelte.

PostgreSQL tidak perlu dipasang di Windows karena berjalan di Docker.

### 2.2 Cek versi

Buka PowerShell baru setelah semua terpasang:

```powershell
git --version
go version
node -v
docker --version
docker compose version
```

Yang diharapkan: `go version go1.27.3 windows/amd64`, `v24.22.1`, dan Docker serta Compose tanpa error. Tulis versi Docker Desktop Anda di `docs/versions.md`, bagian "Alat di komputer pengembang".

### 2.3 Jalankan PostgreSQL 18.6

```powershell
git clone https://github.com/dkpauzi/revioten.git
cd revioten
Copy-Item .env.example .env
[guid]::NewGuid().ToString('N')   # membuat password acak 32 karakter (huruf dan angka)
notepad .env                      # tempel password tadi ke POSTGRES_PASSWORD, lalu simpan
docker compose config --quiet     # tidak ada keluaran berarti file Compose benar
docker compose up -d
docker compose ps                 # tunggu sampai STATUS berisi (healthy)
docker compose exec db psql -U revioten -d revioten -c "select version();"
docker compose down               # mematikan container; data tetap ada di volume
```

Keluaran `select version();` harus diawali `PostgreSQL 18.6`.

**Bila ada masalah:**
- **Port 5432 sudah dipakai** (misalnya ada PostgreSQL lain di Windows): ganti `POSTGRES_PORT` di `.env`, misalnya `5433`.
- **Login gagal setelah `.env` diubah:** password hanya dipakai saat volume pertama kali dibuat. Bila password diganti setelah itu, buat ulang volume dengan `docker compose down -v`. Perintah ini menghapus seluruh isi database.
- **Error terkait `.env`:** Git for Windows bisa mengubah akhir baris file menjadi CRLF. Bila Compose membaca nilai yang aneh dari `.env`, simpan ulang `.env` dengan akhir baris LF (di VS Code: klik "CRLF" di pojok kanan bawah, lalu pilih "LF"). Usulan untuk M0.2: tambah `.gitattributes` supaya akhir baris seragam.

## 3. Bukti M0.1 (container cloud, 27 Oktober 2026)

Go dan Node di cloud dipasang sementara: Go lewat `GOTOOLCHAIN=go1.27.3` (diunduh dari proxy.golang.org), dan Node dari nodejs.org dengan checksum `SHASUMS256.txt` yang cocok. Docker daemon dinyalakan di container itu.

```
$ go version
go version go1.27.3 linux/amd64
$ node -v
v24.22.1
$ npm -v
11.19.1
$ docker compose ps
NAME            IMAGE           STATUS                   PORTS
revioten-db-1   postgres:18.6   Up 3 minutes (healthy)   127.0.0.1:5432->5432/tcp
$ docker compose exec db psql -U revioten -d revioten -c "select version();"
 PostgreSQL 18.6 (Debian 18.6-1.pgdg13+2) on x86_64-pc-linux-gnu, compiled by gcc (Debian 14.2.0-19) 14.2.0, 64-bit
```

Uji tambahan:
- `show data_directory;` menghasilkan `/var/lib/postgresql/18/docker`, sesuai dokumentasi resmi image untuk PostgreSQL 18.
- Tabel uji dibuat, lalu container dimatikan dengan `docker compose down` dan dinyalakan lagi. Isinya masih ada (`count = 1`), jadi volume terpasang di tempat yang benar. Tabel uji lalu dihapus.
- Dari luar container, koneksi lewat `127.0.0.1:5432` dengan password dari `.env` berhasil.
- `git check-ignore` membuktikan `.env` dan `data/` diabaikan git.

## 4. Konsep yang dipelajari

- **Toolchain.** Kumpulan alat yang mengubah kode menjadi program yang jalan. Di proyek ini isinya compiler Go (`go`), runtime dan package manager JavaScript (`node`, `npm`, hanya untuk build layar), dan container (`docker`, `docker compose`) untuk PostgreSQL.
- **Penguncian versi.** Semua mesin memakai versi yang persis sama, supaya hasilnya bisa diulang. Caranya:
  - menulis versi tepat, misalnya `18.6`, bukan `18` atau `latest`;
  - menyimpan lockfile (`go.sum` di M0.2, `package-lock.json` di M0.4) yang mengunci juga dependensi tidak langsung;
  - untuk image Docker, memahami beda tag dan digest. Tag seperti `18.6` adalah nama yang bisa dipindah ke build baru (misalnya untuk patch Debian). Digest `sha256:...` adalah sidik jari isi yang tidak bisa berubah. Di M0.1 kita memakai tag dan mencatat digest-nya di `docs/versions.md`.
- **Aturan versi R-VER.** Hanya rilis stabil (R-VER-01). Runtime memakai line yang masih didukung (R-VER-02). Semua peer dependency cocok tanpa paksaan (R-VER-03). Major baru dipakai setelah ada patch (R-VER-04). Pakai patch terbaru dan catat tanggalnya (R-VER-05).
- **Docker Compose.** Satu file YAML yang menjelaskan container: image, variabel lingkungan, port, volume, dan healthcheck. `up -d` menyalakan di latar, `ps` melihat status, `down` mematikan tanpa menghapus volume, dan `down -v` ikut menghapus volume.
- **Volume.** Tempat data disimpan di luar container, sehingga data tidak hilang saat container dibuat ulang. Sejak image PostgreSQL 18, volume dipasang di `/var/lib/postgresql`, bukan `/var/lib/postgresql/data` seperti di versi lama.
- **Rahasia di `.env`.** Compose membaca `.env` dari folder proyek. `.env` masuk `.gitignore`, dan `.env.example` menjadi contoh yang di-commit. Tanda `${VAR:?pesan}` di `compose.yaml` membuat Compose berhenti dengan pesan jelas bila variabelnya kosong.
- **Port hanya di localhost.** `127.0.0.1:5432:5432` berarti database hanya bisa dibuka dari komputer itu sendiri, tidak dari jaringan kantor (D-36).

## 9. Latihan tulis tangan (tanpa AI)

**Tugas.** Di folder kosong di luar repo, tulis sendiri `compose.yaml` dan `.env` untuk PostgreSQL 18.6 tanpa melihat file di repo. Syaratnya:
1. User, password, dan nama database dibaca dari `.env`, dan Compose berhenti dengan pesan jelas bila password kosong.
2. Port hanya bisa dibuka dari komputer sendiri, di port 5433 (supaya tidak bentrok dengan database proyek).
3. Data disimpan di volume bernama, di path yang benar untuk PostgreSQL 18.
4. Ada healthcheck dengan `pg_isready`.

**Kriteria lulus.**
- `docker compose config --quiet` tanpa error, dan error yang jelas bila `POSTGRES_PASSWORD` dikosongkan.
- `docker compose up -d`, lalu `docker compose ps` menunjukkan `(healthy)`.
- `select version();` menghasilkan PostgreSQL 18.6.
- Buat satu tabel, jalankan `docker compose down` lalu `docker compose up -d`, dan tabelnya masih ada.

**Pertanyaan yang dijawab dengan tulisan sendiri** (2 sampai 3 kalimat per pertanyaan):
1. Apa beda tag `18.6` dan digest `sha256:...`, dan kapan Anda memilih digest?
2. Apa beda `docker compose down` dan `docker compose down -v`?
3. Kenapa port ditulis `127.0.0.1:5433:5432`, bukan `5433:5432`?

Setelah selesai, bandingkan dengan `compose.yaml` di repo dan catat perbedaannya.

## 10. Tambahan 28 Oktober 2026 (setelah M0.1 ditutup)

Keputusan pemilik atas temuan M0.1. Rinciannya ada di `docs/evaluasi-desain.md`.
- **E-11:** kode customer menjadi master data yang bisa diubah nanti, dengan riwayat kode. M0.5 menyimpan kode, lalu mengubah kode beserta riwayatnya dibangun di M1.4. Setelah kode diganti, nomor berjalan untuk kode baru mulai lagi dari awal, dan dokumen model yang masih aktif dipindah manual ke nomor baru.
- **E-12:** struktur nomor mengikuti WI SW-ZZ-000, dan aturannya disimpan sebagai master data: kode pabrik, jenis dokumen, kode customer (termasuk ZZ dan HSE), format nomor berjalan, dan digit revisi. Nomor di atas 999 memakai huruf dan 3 digit (A001 sampai A999, lalu B001), sesuai pernyataan pemilik. SC-ESD-K001 diabaikan karena bukan control plan proses.
- **E-16 (baru, diputuskan):** memindah dokumen aktif ke nomor baru setelah kode customer berganti. Revisi berlanjut, nomor lama menjadi tidak aktif dan tidak bisa diteruskan, pemindahan butuh revisi dan tanda tangan baru, dan dilakukan per dokumen.
- **E-13:** pakai versi stabil atau LTS terbaru. `docs/versions.md` dan CLAUDE.md bagian 4 sudah diperbarui (Svelte 5.57.3, oapi-codegen v2.8.1, Gotenberg v8.39.0). Cek ulang 28 Oktober 2026 tidak menemukan versi baru lain.
- **E-14:** diputuskan. Masa tunggu 14 hari untuk line yang baru punya satu rilis (bila tidak ada alternatif) dan untuk paket 0.x. `@sveltejs/adapter-static` 4.0.0 boleh dipakai di M0.4 sebagai pengecualian tercatat. River memakai versi terbaru yang memenuhi masa tunggu saat pertama dipakai (per 28 Oktober 2026: v0.49.0).
- **E-15 (baru):** belum ada langkah desain layar. Pemilik setuju wireframe dibuat sebelum Tahap 4. Posisinya di milestone ditentukan di sesi desain, dan bahasa UI (Q-14) perlu diputuskan dulu.
- **Docker:** tetap dipakai. Bila Docker Desktop terkendala lisensi atau izin IT, pakai Docker Engine di dalam WSL 2. PostgreSQL langsung di Windows hanya cadangan terakhir, dan akan dicatat sebagai temuan bila dipakai, karena brief memakai Docker (R-SEC-04, D-36).

Dokumen referensi dari pemilik (set TR-021: SH, SF, dan SC untuk satu model) dibaca sebagai acuan dan **tidak disimpan di repo**, sesuai permintaan pemilik. Bila dibutuhkan lagi, simpan di `data/` di komputer pemilik. Pengamatan darinya, tanpa nama orang, dicatat di bagian akhir `docs/evaluasi-desain.md` sebagai bahan item F di brief bagian 21. Sebagian besar menguatkan F-03, F-05, F-06, dan F-07, dan ada dua yang baru: nama file PFMEA tertinggal satu revisi dari isinya, dan isian "Process or Line" berbeda di dalam satu set.
