# M4.7 · Salin komposisi model lain

- **Tanggal:** 14 November 2026
- **Milestone:** M4.7 "Salin komposisi model lain. Mulai dari komposisi model serupa lalu sesuaikan. Selesai bila salinan menjadi dokumen mandiri."
- **Aturan yang dipakai:** R-CMP-05 (model boleh mulai dari komposisi model lain), R-CMP-03, R-CMP-04, R-DOC-02 (ID baris tetap dan milik satu dokumen).
- **Persetujuan pemilik:** "sekarang tolong lanjutkan" (14 November 2026).

## 1. Tujuan dan apa yang dibuat

1. Tombol **Copy from another model** tampil selama dokumen belum punya baris. Panelnya menampilkan dokumen lain milik customer yang sama, berjenis sama, dan sudah berisi baris, lengkap dengan nama model dan jumlah barisnya.
2. **Copy rows** menyalin baris (urutan, proses, nomor operasi, isi, tautan ke poin template) dan poin yang dikecualikan. Seluruh set ikut: PFD dari PFD, PFMEA dari PFMEA, CP dari CP.
3. **Salinan mandiri.** Baris salinan mendapat ID baru; mengubah salinan tidak mengubah sumbernya.
4. Daftar dokumen (`GET /api/v1/documents`) sekarang membawa nama model setiap dokumen.

| Bagian | File |
|---|---|
| Aturan | `internal/document/copy.go` (`CopyFrom`) |
| Query | `CopyDocumentRows`, `CopyPointExclusions`, `model_names` di `ListDocuments` |
| API | `copyDocumentComposition`, skema `DocumentCopy`, `models` di `DocumentSummary` |
| Layar | `web/src/lib/documents/CopyPanel.svelte` |
| Test | `TestCopyFrom`, `TestListDocumentModels`, `m4-compose.test.ts` |

Tidak ada migrasi baru: `INSERT ... SELECT` memakai tabel yang sudah ada.

## 2. Cara mengulang dari nol

1. Tulis `TestCopyFrom`: set sumber dirakit, satu poin dicoret, satu baris diketik, diurutkan; lalu disalin ke set model lain dan dibandingkan baris demi baris.
2. Tulis query `INSERT INTO document_rows (...) SELECT ... FROM document_rows WHERE document_id = sumber`.
3. Tulis `CopyFrom`: periksa hak, kunci dokumen tujuan, pasangkan dokumen per jenis, tolak bila tujuan sudah berisi.
4. Kontrak API, handler, panel, dan teks dua bahasa.

## 3. Konsep yang dipelajari

- **`INSERT ... SELECT`.** Menyalin banyak baris dalam satu perintah SQL, tanpa membawanya ke Go dulu. Kolom `id` tidak disebut, jadi database membuat ID baru.
- **Salin vs tautkan.** Salinan adalah data baru yang lepas dari sumbernya. Yang tetap sama hanya tautan ke **poin template**, karena dua model memang memakai poin yang sama.
- **Syarat di awal transaksi.** Semua pemeriksaan (customer, jenis, versi form, tujuan kosong) dilakukan sebelum ada yang ditulis, jadi tidak ada salinan setengah jadi.

## 4. Keputusan dan alasannya

| Keputusan | Alasan |
|---|---|
| Hanya ke dokumen yang masih kosong | Menghindari baris kembar dan pertanyaan "mana yang menang" |
| Hanya dari customer yang sama | Poin dan varian bisa khusus customer; data lintas customer tidak boleh bocor |
| Versi form harus sama | Isi baris disimpan per ID kolom versi form itu (R-DOC-01) |
| Header tidak disalin | Header diisi tangan per model (R-CMP-01) |
| Nomor operasi ikut tersalin beserta tanda manualnya | Alur model serupa biasanya sama; penyusun bisa menomori ulang di panel urutan |

## 5. Asumsi

- Teks varian mengikuti model sumber. Bila model baru punya varian sendiri, penyusun menyesuaikan barisnya; perbandingan dengan template ada di M4.8.
