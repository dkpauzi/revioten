# M4.3 · Penguncian optimistik

- **Tanggal:** 13 November 2026
- **Milestone:** M4.3 "Penguncian optimistik. Dua pengguna mengedit bersamaan tidak saling menimpa. Selesai bila konflik terdeteksi dan ditampilkan."
- **Aturan yang dipakai:** R-DOC-07 (penguncian optimistik), R-API-13 (satu format error).
- **Persetujuan pemilik:** "kerjakan dulu hingga semua M4 selesai" (12 November 2026).

## 1. Tujuan dan apa yang dibuat

1. **Versi per baris dan per header.** Setiap baris dokumen punya angka `version`, dan header dokumen punya `header_version`. Angkanya naik satu setiap kali disimpan.
2. **Simpan hanya bila versinya masih sama.** Layar mengirim balik versi yang dibacanya. Server menyimpan hanya bila versi di database masih sama; bila tidak, jawabannya 409 dengan kode `changed` dan tidak ada yang tersimpan.
3. **Konflik ditampilkan.** Layar menampilkan pesan "Someone else changed this row while you were editing…", memuat isi terbaru, dan penyusun mengetik ulang perubahannya di atas isi terbaru itu. Header berlaku sama.
4. **Perbaikan workbook (bug laten M4.2).** Saat sel dibuka, lebar tabel bisa berubah (scrollbar halaman muncul), lalu Tabulator menggambar ulang semua baris dan membuang sel yang sedang diketik. Sekarang gambar ulang ditunda sampai sel selesai diedit, dan tabel hanya diisi ulang bila daftar baris dari server memang berganti.

## 2. Cara mengulang dari nol

1. Tulis test dulu: dua pembaca memegang versi 1; yang pertama menyimpan berhasil, yang kedua ditolak dengan `version:changed`, dan isi baris tetap milik yang pertama. Lalu test 10 penyimpanan paralel dengan versi yang sama: tepat satu yang berhasil.
2. Migrasi: `ALTER TABLE document_rows ADD COLUMN version integer NOT NULL DEFAULT 1` dan `documents.header_version`.
3. Query: `UPDATE ... SET version = version + 1 WHERE id = $1 AND version = $expected`. Pakai `:execrows` supaya Go tahu berapa baris yang berubah; 0 berarti konflik.
4. Kontrak API, `go generate ./...`, handler, lalu `npm --prefix web run gen:api`.
5. Layar: `gridRow` menyimpan `_version`, `rowInputFrom` mengirimnya, dan sesudah simpan berhasil versi baru dicatat di baris tabel.
6. Test E2E: "orang lain" ditiru dengan `fetch` langsung dari halaman, lalu sel diketik di tabel.

## 3. Konsep yang dipelajari

- **Penguncian optimistik vs pesimistik.** Pesimistik mengunci data selama orang mengedit (orang lain menunggu). Optimistik tidak mengunci; ia hanya memeriksa saat menyimpan apakah data masih seperti saat dibaca. Cocok bila konflik jarang, seperti dua orang mengedit baris yang sama.
- **Periksa dan ubah dalam satu perintah SQL.** Syarat `WHERE version = ...` berada di perintah `UPDATE` yang sama, jadi database yang menjamin hanya satu dari dua penyimpanan bersamaan yang menang. Memeriksa di Go saja tidak cukup, karena di antara baca dan tulis orang lain bisa masuk.
- **Antrean promise.** `queue = queue.then(...)` membuat penyimpanan berjalan satu per satu. Tanpa itu, dua sel di baris yang sama yang diubah cepat akan mengirim versi yang sama, dan yang kedua ditolak sebagai konflik palsu.
- **Per baris, bukan per dokumen.** Dua orang boleh mengedit baris berbeda di dokumen yang sama tanpa konflik.

## 4. Keputusan dan alasannya

| Keputusan | Alasan |
|---|---|
| Versi berupa angka, bukan `updated_at` | Angka tidak bergantung pada ketelitian jam, dan mudah dibaca di test |
| Versi wajib dikirim saat mengubah baris (`version:required`) | Klien yang lupa mengirim versi tidak boleh diam-diam menimpa |
| Saat konflik, seluruh dokumen dimuat ulang | Sederhana, dan penyusun melihat keadaan terbaru semua baris |
| Ketikan yang kalah tidak digabung otomatis | Menggabung isi sel bisa menghasilkan kalimat yang salah di dokumen mutu; penyusun yang memutuskan |

## 5. Asumsi

- Menambah dan menghapus baris tidak memakai versi: menambah tidak menimpa apa pun, dan menghapus baris yang baru diubah orang lain tetap diizinkan (penghapusan tercatat di audit log). Bila pemilik ingin hapus juga diperiksa versinya, ini perubahan kecil.

## 8. Latihan tulis tangan

Tanpa AI, di psql: buat tabel `catatan (id int primary key, isi text, version int not null default 1)` dan isi satu baris. Buka dua jendela psql. Di keduanya baca barisnya (versi 1). Di jendela pertama jalankan `UPDATE catatan SET isi = 'A', version = version + 1 WHERE id = 1 AND version = 1;`, lalu di jendela kedua perintah yang sama dengan isi 'B'. Catat tulisan `UPDATE 1` dan `UPDATE 0`, dan jelaskan dengan kata-kata sendiri kenapa yang kedua tidak mengubah apa pun.
