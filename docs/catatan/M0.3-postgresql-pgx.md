## 2. Cara mengulang dari nol (Windows)

Prasyarat: Go 1.27.3 dan Docker Desktop yang **sedang berjalan** (catatan M0.1 bagian 2).

```powershell
git pull
go test ./...                 # pertama kali lebih lama: mengunduh image postgres:18.6 dan testcontainers/ryuk
go test -v ./internal/db/     # melihat setiap test dan pesan errornya
go test -short ./...          # tanpa Docker: test database dilewati
go vet ./...
gofmt -l .
```

Untuk latihan psql di bagian 4:

```powershell
docker compose up -d
docker compose exec db psql -U revioten -d revioten
```

Lalu ketik atau tempel perintah SQL dari bagian 4. Keluar dari psql dengan `\q`.

**Catatan Windows (belum dicoba di komputer pemilik):**
- Bila Docker belum berjalan, `go test ./...` gagal dengan pesan "gagal menyalakan PostgreSQL untuk test" dan saran memakai `-short`.
- testcontainers-go menyalakan container kecil bernama Ryuk (`testcontainers/ryuk:0.14.0`), yang membuang container test setelah test selesai. Bila ada error yang menyebut Ryuk, coba sekali dengan `$env:TESTCONTAINERS_RYUK_DISABLED="true"`. Dalam mode itu container dibuang oleh `TestMain` sendiri. Bila test berhenti di tengah jalan, periksa container sisa dengan `docker ps -a`.
- Bila Anda memakai Docker Engine di dalam WSL 2 (cadangan dari keputusan Docker), jalankan repo, Go, dan `go test` di dalam WSL 2 juga.

## 4. Latihan psql: JSONB, indeks, dan transaksi

Dikerjakan di database Compose, di skema `latihan` yang dihapus lagi di akhir, jadi database pengembangan tetap bersih. Hasil di bawah berasal dari cloud; ulangi di komputer Anda dan bandingkan.

```sql
CREATE SCHEMA latihan;
SET search_path TO latihan;

-- 1. Tabel dengan kolom JSONB
CREATE TABLE practice_rows (
    id      bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    process text   NOT NULL,
    content jsonb  NOT NULL
);
INSERT INTO practice_rows (process, content) VALUES
    ('IQC', '{"point": "cek label supplier", "rpn": 84}'),
    ('IQC', '{"point": "cek jumlah", "rpn": 60}'),
    ('SMT', '{"point": "cek hasil solder", "rpn": 120, "critical": true}');

-- 2. Membaca isi JSONB: ->> mengambil nilai sebagai teks, ::int mengubahnya ke angka
SELECT id, process, content->>'point' AS point, (content->>'rpn')::int AS rpn
FROM practice_rows ORDER BY id;

-- 3. Mencari berdasarkan isi JSONB
SELECT id, content->>'point' AS point FROM practice_rows WHERE content @> '{"critical": true}';
SELECT id, content->>'point' AS point FROM practice_rows WHERE (content->>'rpn')::int > 100;
```
Hasil langkah 2 dan 3:
```
 id | process |       point        | rpn
  1 | IQC     | cek label supplier |  84
  2 | IQC     | cek jumlah         |  60
  3 | SMT     | cek hasil solder   | 120

 id |      point          (kedua query menghasilkan baris yang sama)
  3 | cek hasil solder
```

```sql
-- 4. Indeks: tambah 10.000 baris supaya efek indeks terlihat
INSERT INTO practice_rows (process, content)
SELECT 'P' || lpad(g::text, 5, '0'),
       jsonb_build_object('point', 'poin ' || g, 'rpn', g % 200)
FROM generate_series(1, 10000) AS g;
ANALYZE practice_rows;

EXPLAIN (COSTS OFF) SELECT * FROM practice_rows WHERE process = 'P00042';
CREATE INDEX practice_rows_process_idx ON practice_rows (process);
EXPLAIN (COSTS OFF) SELECT * FROM practice_rows WHERE process = 'P00042';

EXPLAIN (COSTS OFF) SELECT * FROM practice_rows WHERE content @> '{"critical": true}';
CREATE INDEX practice_rows_content_idx ON practice_rows USING gin (content);
EXPLAIN (COSTS OFF) SELECT * FROM practice_rows WHERE content @> '{"critical": true}';
```
Hasil langkah 4, sebelum dan sesudah indeks:
```
Seq Scan on practice_rows                                      (sebelum indeks B-tree)
  Filter: (process = 'P00042'::text)
Index Scan using practice_rows_process_idx on practice_rows    (sesudah)
  Index Cond: (process = 'P00042'::text)

Seq Scan on practice_rows                                      (sebelum indeks GIN)
  Filter: (content @> '{"critical": true}'::jsonb)
Bitmap Heap Scan on practice_rows                              (sesudah)
  Recheck Cond: (content @> '{"critical": true}'::jsonb)
  ->  Bitmap Index Scan on practice_rows_content_idx
```

```sql
-- 5. Transaksi: ROLLBACK membatalkan, COMMIT menyimpan
SELECT count(*) FROM practice_rows;                                          -- 10003
BEGIN;
INSERT INTO practice_rows (process, content) VALUES ('AOI', '{"point": "batal"}');
SELECT count(*) FROM practice_rows;                                          -- 10004
ROLLBACK;
SELECT count(*) FROM practice_rows;                                          -- 10003 lagi
BEGIN;
INSERT INTO practice_rows (process, content) VALUES ('AOI', '{"point": "jadi"}');
COMMIT;
SELECT count(*) FROM practice_rows;                                          -- 10004

-- 6. Bersihkan
RESET search_path;
DROP SCHEMA latihan CASCADE;
```

**Percobaan dua sesi (isolasi).** Buka dua jendela psql:
1. Di jendela A, jalankan `BEGIN;` lalu `INSERT ...;` tanpa COMMIT.
2. Di jendela B, hitung barisnya. Baris dari A belum terlihat.
3. Jalankan `COMMIT;` di A.
4. Hitung lagi di B. Barisnya sekarang terlihat.

Di cloud hasilnya: sesi B melihat 0 baris sebelum A melakukan COMMIT, lalu 1 baris sesudahnya. Inilah isolasi *read committed*, bawaan PostgreSQL.

## 5. Konsep yang dipelajari

- **SQL dasar.** `CREATE TABLE` dengan tipe kolom, `PRIMARY KEY` sebagai identitas baris, dan `GENERATED ALWAYS AS IDENTITY` untuk id otomatis. `INSERT ... RETURNING id` mengembalikan id baris yang baru dibuat.
- **JSONB.**
  - `->>` mengambil satu nilai sebagai teks, dan `::int` mengubahnya ke angka;
  - `@>` bertanya "apakah JSON ini memuat potongan ini";
  - `jsonb_build_object` membuat JSON dari nilai kolom.
  - Dari Go, pgx mengubah struct menjadi JSONB lewat `encoding/json` (tag `json:"..."`) dan mengubahnya kembali saat membaca. Hati-hati: string Go dikirim apa adanya sebagai teks JSON, jadi kirimlah struct atau map, bukan string.
- **Indeks.** B-tree untuk perbandingan kolom biasa (`=`, `<`, urutan), dan GIN untuk isi JSONB (`@>`). `EXPLAIN` menunjukkan rencana query: `Seq Scan` membaca seluruh tabel, sedangkan `Index Scan` dan `Bitmap Index Scan` memakai indeks. `ANALYZE` memperbarui statistik yang dipakai perencana. Pada tabel yang sangat kecil, `Seq Scan` tetap dipilih karena lebih murah.
- **Transaksi.** BEGIN, lalu COMMIT atau ROLLBACK: semua perubahan tersimpan bersama atau tidak sama sekali. Sesi lain tidak melihat perubahan yang belum di-COMMIT (*read committed*). Ini dasar penomoran tanpa bentrok di M2.2 (R-NUM-03).
- **Connection pool.** `pgxpool.ParseConfig` membaca alamat, `pgxpool.NewWithConfig` membuat pool, `Ping` memastikan database bisa dihubungi, dan `Close` menutup semua koneksi. Pool memakai ulang koneksi, karena membuka koneksi baru setiap kali itu mahal.
- **`context.Context`.** Setiap panggilan pgx menerima `ctx` untuk batas waktu dan pembatalan. Di test dipakai `t.Context()`, yang otomatis batal saat test selesai. Parameter `connect_timeout` di alamat membatasi lama menunggu koneksi.
- **`defer`.** `defer tx.Rollback(ctx)` menjadwalkan ROLLBACK untuk semua jalan keluar, termasuk panic. Setelah COMMIT berhasil, ROLLBACK tidak mengubah apa-apa. pgx juga menyediakan `pgx.BeginFunc` dengan perilaku yang sama; `WithTx` ditulis sendiri supaya polanya dipahami.
- **Error berlapis.** `fmt.Errorf("...: %w", err)` menambah keterangan tanpa menghilangkan error asli, dan `errors.Is` memeriksa error asli di dalam lapisan itu (dipakai di `TestWithTxRollback`). Detail teknis yang bisa memuat rahasia tidak diteruskan (E-18).
- **Test integrasi dengan testcontainers.**
  - `TestMain` berjalan sekali untuk satu package: menyalakan container, menjalankan semua test (`m.Run`), lalu membuang container.
  - `go test -short` bersama `testing.Short()` melewati test yang butuh Docker.
  - `t.Helper()` membuat baris error menunjuk ke pemanggil, `t.Cleanup` menjadwalkan penutupan, dan `t.Skip` melewati test.
- **Modul Go.** `go.mod` mencatat dependensi langsung dan tidak langsung (`// indirect`). `go.sum` menyimpan sidik jari setiap modul, `go mod tidy` merapikan keduanya sesuai import yang dipakai, dan `go mod verify` memeriksa bahwa modul di komputer cocok dengan sidik jarinya.

## 7. Asumsi

1. User dan password `test` di container test bukan rahasia: container itu sementara dan dibuang setelah test.
2. ASUMSI E-18: rahasia tidak boleh muncul di pesan error. Sampai diputuskan, `Connect` memakai pesan umum untuk alamat yang tidak bisa dibaca.
3. Test "server tidak ada" memakai `connect_timeout=5`, supaya test tidak menggantung lama bila sistem operasi lambat menolak koneksi.
4. Dua role database (pemilik dan aplikasi, E-06) baru dibuat di M1.3. Di M0.3 aplikasi belum tersambung ke database pengembangan.

## 8. Temuan desain

- **E-18 (baru, terbuka):** belum ada aturan bahwa password, token, dan alamat koneksi tidak boleh muncul di log, pesan error, atau audit log. Rekomendasi: tambah aturan keamanan baru, dan buktikan dengan test seperti `TestConnectError`. Tidak menghambat.

## 10. Latihan tulis tangan (tanpa AI)

**Tugas: pindah stok yang tidak boleh setengah jadi.** Di folder kosong di luar repo, tanpa melihat kode di repo:
1. Buat modul baru (`go mod init latihan/m03`) dan pasang pgx v5.11.0.
2. Nyalakan database Compose. Di psql, buat skema `latihan` dan tabel:
   ```sql
   CREATE SCHEMA latihan;
   CREATE TABLE latihan.stock (item text PRIMARY KEY, qty int NOT NULL CHECK (qty >= 0));
   INSERT INTO latihan.stock VALUES ('A', 10), ('B', 0);
   ```
3. Tulis `main.go` yang membaca alamat database dari variabel lingkungan `DATABASE_URL`, lalu memanggil `Connect` dan `WithTx` versi tulisan Anda sendiri.
4. Buat fungsi `move(ctx, pool, from, to, qty)` yang mengurangi stok `from` dan menambah stok `to` di **satu transaksi**.
5. Panggil `move` dua kali, lalu cetak isi tabel setelah setiap panggilan:
   - pindahkan 4 dari A ke B (harus berhasil);
   - pindahkan 20 dari A ke B (harus gagal karena `CHECK`).

**Kriteria lulus.**
- Setelah perpindahan pertama: A = 6, B = 4.
- Setelah perpindahan kedua: A tetap 6, B tetap 4, dan program mencetak error dari PostgreSQL. Tidak ada setengah perubahan, misalnya B bertambah padahal A gagal dikurangi.
- `go vet ./...` bersih, dan `gofmt -l .` tanpa keluaran.

Di PowerShell, variabel lingkungan diisi dengan `$env:DATABASE_URL="postgres://revioten:<password-anda>@127.0.0.1:5432/revioten?sslmode=disable"`. Jangan menyimpan password itu di file yang di-commit.

**Pertanyaan yang dijawab dengan tulisan sendiri** (2 sampai 3 kalimat per pertanyaan):
1. Kenapa `defer tx.Rollback(ctx)` aman dipanggil walaupun transaksi sudah di-COMMIT?
2. Apa bedanya memakai pool dengan membuka satu koneksi baru untuk setiap permintaan?
3. Kenapa `Connect` tidak meneruskan pesan error asli pgx untuk alamat yang salah format?

Setelah selesai, hapus skema latihan (`DROP SCHEMA latihan CASCADE;`), lalu bandingkan kode Anda dengan `internal/db` di repo.
