- **Tanggal:** 14 November 2026
- **Milestone:** M4.10 "Diagram PFD (opsional). Svelte Flow dan ELK. Selesai bila diagram terbentuk otomatis dari daftar proses."
- **Aturan yang dipakai:** brief bagian 7 (Svelte Flow dengan ELK untuk diagram PFD), R-VER-01 sampai R-VER-05 dan E-14 (versi paket), D-150 (kolom dicari lewat key). Usulan simbol TR-020 di milestone tidak dibangun terpisah: pilihan Flow Symbol dan NG Disposition sudah ada di form PFD isi awal.
- **Persetujuan pemilik:** "sekarang tolong lanjutkan" (14 November 2026).

## 1. Tujuan dan apa yang dibuat

1. Di dokumen PFD, tombol **Show the diagram** menggambar alur dari baris dokumen: satu kotak per baris menurut urutannya, berisi nomor operasi dan nama proses, dihubungkan panah.
2. **Bentuk kotak** mengikuti kolom Flow Symbol (process, alternate process, decision, connector, merge, document). **NG Disposition** (scrap, NCP, rework) digambar sebagai simbol bergaris putus di samping langkahnya, dengan panah NG.
3. **Letak otomatis** dihitung ELK (algoritma layered, dari atas ke bawah). Diagram hanya dibaca; mengubah baris di tabel menggambar ulang diagramnya.
4. Diagram dimuat hanya saat dibuka, karena ELK cukup besar (sekitar 1,6 MB sebelum kompresi).

| Bagian | File |
|---|---|
| Penyusun diagram | `web/src/lib/pfdDiagram.ts` (`diagramOf`) |
| Layar | `web/src/lib/documents/PfdDiagram.svelte`, `PfdNode.svelte`, halaman dokumen |
| Paket | `@xyflow/svelte` 1.7.1, `elkjs` 0.12.1 (lihat `docs/versions.md`) |
| Test | `pfdDiagram.spec.ts`, `m4-compose.test.ts` |

Tidak ada perubahan backend: diagram memakai baris yang sudah ada.

## 2. Cara mengulang dari nol

1. Cek versi: `npm view @xyflow/svelte dist-tags time --json` dan `npm view elkjs dist-tags time --json`, lalu `npm view @xyflow/svelte@1.7.1 peerDependencies`. elkjs paket 0.x, jadi pastikan sudah lewat 14 hari.
2. Pasang: `npm --prefix web install --save-dev --save-exact @xyflow/svelte@1.7.1 elkjs@0.12.1`.
3. README paket masih contoh gaya lama (`writable`). Untuk v1, baca tipe di `node_modules/@xyflow/svelte/dist/lib/container/SvelteFlow/types.d.ts`: `nodes` dan `edges` adalah array biasa yang di-`bind`.
4. Tulis `pfdDiagram.spec.ts`, lalu `diagramOf`.
5. Tulis `PfdNode.svelte` (bentuk per simbol dengan CSS) dan `PfdDiagram.svelte` (ELK lalu Svelte Flow).

## 3. Konsep yang dipelajari

- **Susun dulu, gambar kemudian.** `diagramOf` hanya memutuskan simpul dan panah. ELK hanya menghitung letak. Svelte Flow hanya menggambar. Tiga tugas terpisah, jadi masing-masing mudah diganti.
- **`$state.raw`.** Array simpul diganti utuh setiap kali, tidak diubah per bagian, jadi tidak perlu dilacak Svelte sampai ke dalam.
- **Membatalkan hasil usang.** ELK berjalan asinkron. Bila baris berubah lagi sebelum ELK selesai, hasil lama dibuang (`current = false` di fungsi pembersih `$effect`).
- **Impor dinamis.** `{#await import(...)}` memisahkan kode yang besar ke potongan sendiri yang dimuat hanya saat diperlukan.
- **Bentuk dengan CSS.** `clip-path: polygon(...)` membuat belah ketupat (decision) dan segitiga (merge) tanpa gambar.
