## 2. Cara mengulang dari nol (Windows)

Prasyarat: Git dan Go 1.27.3 sudah terpasang (catatan M0.1 bagian 2). Docker belum dibutuhkan.

```powershell
git clone https://github.com/dkpauzi/revioten.git   # atau "git pull" bila sudah ada
cd revioten
go version          # harus go1.27.3
go test ./...       # harus "ok" untuk internal/server
go vet ./...        # tanpa keluaran berarti bersih
gofmt -l .          # tanpa keluaran berarti semua file rapi
go run ./cmd/revioten
```

Biarkan jendela itu terbuka, lalu buka jendela PowerShell kedua:

```powershell
curl.exe -i http://127.0.0.1:8080/health            # 200 dan {"status":"ok"}
Invoke-RestMethod http://127.0.0.1:8080/health      # menampilkan kolom status bernilai ok
curl.exe -i -X POST http://127.0.0.1:8080/health    # 405 Method Not Allowed
curl.exe -i http://127.0.0.1:8080/tidak-ada         # 404
```

Hentikan server dengan Ctrl+C di jendela pertama. Untuk membuat file program:

```powershell
go build -o bin/revioten.exe ./cmd/revioten
.\bin\revioten.exe
```

**Catatan Windows (belum dicoba di komputer pemilik):**
- Pakai `curl.exe`, bukan `curl`. Di Windows PowerShell 5.1, `curl` adalah nama lain untuk `Invoke-WebRequest`, sehingga opsinya berbeda.
- Bila port 8080 sudah dipakai, server berhenti dengan pesan `bind: ... address already in use` atau pesan sejenis. Jalankan di port lain: `go run ./cmd/revioten -addr 127.0.0.1:8081`.
- `.gitattributes` membuat file yang di-checkout memakai akhir baris LF. Bila Anda sudah meng-clone repo sebelum file ini ada dan `gofmt -l .` menampilkan nama file, jalankan sekali `git rm --cached -r -q .` lalu `git reset --hard` supaya semua file di-checkout ulang dengan LF. Perintah ini membuang perubahan yang belum di-commit, tapi tidak menyentuh `.env`.

## 4. Konsep yang dipelajari

- **Module dan package.** `go.mod` adalah identitas proyek: nama modul dan versi Go minimal. Satu folder berisi satu package. `package main` dengan fungsi `main()` menjadi program, sedangkan package lain menjadi pustaka. Package di bawah `internal/` hanya bisa di-import dari dalam modul ini sendiri.
- **Versi Go di `go.mod`.** Baris `go 1.27.3` adalah versi minimal. Bila Go yang terpasang lebih lama, perintah `go` otomatis mengunduh dan memakai toolchain 1.27.3 (pengaturan `GOTOOLCHAIN=auto`). Ini terlihat di cloud: Go bawaan 1.24.7, tapi `go version` di dalam repo menampilkan 1.27.3.
- **Struct dan tag JSON.** `healthResponse` punya satu field `Status`. Tag `` `json:"status"` `` membuatnya ditulis sebagai `"status"` di JSON. Field harus diawali huruf besar supaya bisa dibaca package `encoding/json`.
- **Error.** Go tidak punya exception. Fungsi yang bisa gagal mengembalikan `error`, dan kita memeriksanya dengan `if err != nil`. Contohnya ada di `main.go` (port sudah dipakai) dan di `health.go` (gagal menulis JSON).
- **Handler dan ServeMux.** Handler adalah fungsi `func(w http.ResponseWriter, r *http.Request)`. `ServeMux` mencocokkan pola `"GET /health"` dengan handler-nya. Method lain otomatis dijawab 405 dengan header `Allow: GET, HEAD`, path yang tidak terdaftar dijawab 404, dan HEAD ikut dilayani.
- **Urutan menulis respons.** Header diatur dulu (`w.Header().Set`), lalu kode status (`w.WriteHeader`), lalu isi. Setelah isi mulai ditulis, header dan kode status tidak bisa diubah lagi.
- **Test dengan `httptest`.** `httptest.NewRequest` membuat permintaan palsu, dan `httptest.NewRecorder` merekam jawabannya tanpa membuka port. Table-driven test menaruh beberapa kasus dalam satu tabel. `t.Run` menjadikan setiap kasus subtest yang punya nama sendiri.
- **Siklus test dulu.** Merah karena belum bisa dikompilasi, merah karena perilaku belum ada, hijau, lalu rapikan. Merah kedua penting: ia membuktikan test benar-benar memeriksa perilaku, bukan hanya lulus dengan sendirinya.
- **Alat bawaan Go.** `gofmt` merapikan format kode (tidak ada perdebatan gaya), `go vet` mencari kesalahan umum, dan `go test ./...` menjalankan semua test di semua package.
- **Program dan konfigurasi sederhana.** Package `flag` membaca opsi baris perintah (`-addr`). `http.Server` dengan `ReadHeaderTimeout` mencegah klien yang sangat lambat menahan koneksi. Package `log/slog` menulis log terstruktur (`kunci=nilai`).

## 9. Latihan tulis tangan (tanpa AI)

**Tugas.** Di folder kosong di luar repo, tanpa melihat kode di repo:
1. Buat modul baru: `go mod init latihan/m02`.
2. Tulis **test dulu** di `internal/server/halo_test.go`, berupa table-driven test dengan tiga kasus:
   - `GET /halo` menghasilkan 200 dan JSON `{"pesan":"halo"}`;
   - `GET /halo?nama=Operator` menghasilkan 200 dan JSON `{"pesan":"halo, Operator"}`;
   - `POST /halo` menghasilkan 405.
3. Jalankan `go test ./...` dan pastikan gagal dulu, lalu tulis `NewHandler()` dan handlernya sampai lulus. Petunjuk: nilai `nama` dibaca dengan `r.URL.Query().Get("nama")`.
4. Tulis `cmd/latihan/main.go` dengan flag `-addr` (bawaan `127.0.0.1:8090`), lalu coba dengan `curl.exe`.

**Kriteria lulus.**
- Anda melihat test gagal sebelum kodenya ditulis.
- `go test ./...` lulus, `go vet ./...` bersih, dan `gofmt -l .` tanpa keluaran.
- `curl.exe "http://127.0.0.1:8090/halo?nama=Operator"` menampilkan `{"pesan":"halo, Operator"}`.

**Pertanyaan yang dijawab dengan tulisan sendiri** (2 sampai 3 kalimat per pertanyaan):

2. Apa yang terjadi bila `w.WriteHeader(http.StatusCreated)` dipanggil setelah isi respons ditulis? Coba, lalu baca log-nya.
3. Kenapa alamat bawaannya `127.0.0.1:8090`, bukan `:8090`?
