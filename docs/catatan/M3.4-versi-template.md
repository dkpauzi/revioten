# M3.4 · Versi template

- **Tanggal:** 10 dan 11 November 2026
- **Milestone:** M3.4 "Versi template. Draft dan terbit, tanpa propagasi dulu. Selesai bila versi terbit tidak bisa diubah."
- **Aturan yang dipakai:** R-TPL-05 (draft lalu terbit, versi terbit tidak berubah), R-TPL-02 dan R-TPL-04 (ID field dan poin tetap), R-TPL-06 (template tidak pernah mengubah dokumen langsung), D-64, E-06.
- **Persetujuan pemilik:** "lanjutkan hingga M3 selesai semua" (10 November 2026).

## 1. Tujuan dan apa yang dibuat

Sebelum M3.4 setiap template hanya punya versi 1 berstatus draft, dan status itu belum pernah berubah. Sekarang:

```
versi 1 draft  --Publish-->  versi 1 terbit (hanya bisa dibaca)
                                  |
                                  +--New version-->  versi 2 draft (salinan versi 1)
```

1. **Terbitkan.** Versi draft diterbitkan dengan tombol **Publish version N**, setelah konfirmasi. Format template oleh admin (A-2), process template oleh Pengelola template (E-6).
2. **Versi terbit tidak bisa diubah.** Dijaga di tiga tempat:
   - layar: tombol tambah, ubah, dan simpan hilang;
   - layanan: setiap perubahan dijawab 409 `status:not_allowed`;
   - database: trigger menolak INSERT, UPDATE, DELETE, dan TRUNCATE pada versi terbit dan isinya, juga untuk pemilik database.
3. **Versi baru.** Tombol **New version** membuat versi draft berikutnya sebagai salinan versi terbit terakhir, dengan ID field, sub-proses, poin, dan varian yang sama. Satu template paling banyak punya satu draft.
4. **Pemilih versi.** Versi lama tetap bisa dibuka dan dibaca.
5. **Belum ada propagasi.** Versi baru tidak mengubah dokumen apa pun (dokumen juga belum ada). Propagasi dikerjakan di M5.8.

## 2. Cara mengulang dari nol

1. Tulis test dulu: `internal/template/version_test.go` (enam test), baris baru di `TestPermissionsPerOperation`, `web/src/lib/versions.spec.ts`, dan `web/e2e/versions.test.ts`. `go vet ./internal/template/` harus gagal karena metodenya belum ada.
2. Tulis migrasi 00016, tambah query, lalu `go generate ./...`.
3. Tulis `version.go` sampai `go test -p 1 ./internal/template/` lulus.
4. Tambah empat operasi di `api/openapi.yaml`, jalankan `go generate ./...` dan `npm --prefix web run gen:api`, lalu tulis handler.
5. Tulis `versions.ts`, `VersionBar.svelte`, dan sambungkan ke kedua halaman.
6. Jalankan `npm --prefix web run check`, `npm --prefix web test`, dan `npm --prefix web run test:e2e`.

## 3. Konsep yang dipelajari

- **Aturan dijaga di database, bukan hanya di kode.** Trigger `BEFORE` menolak perubahan sebelum baris ditulis. Dengan begitu aturan tetap berlaku bila seseorang memakai psql langsung. Polanya sama dengan audit log (R-SEC-03).
- **Trigger dengan argumen.** Satu fungsi `template_content_reject_change` dipakai enam tabel; nama tabel versinya diberikan lewat `TG_ARGV[0]`.
- **Indeks unik sebagian.** `CREATE UNIQUE INDEX ... WHERE status = 'draft'` membuat aturan "paling banyak satu draft per template" tanpa kode.
- **Menyalin dengan `INSERT ... SELECT`.** Isi versi disalin di dalam database dalam satu perintah per tabel, tanpa membaca baris ke Go.
- **Test dengan role aplikasi menemukan hak yang kurang.** Mengunci baris `process_templates` (`FOR NO KEY UPDATE`) ditolak, karena role aplikasi tidak punya UPDATE di tabel itu. Solusinya bukan menambah hak, melainkan mengandalkan indeks unik.

## 4. Keputusan dan alasannya

| Keputusan | Alasan |
|---|---|
| Versi baru menyalin ID yang sama, bukan membuat ID baru | Dokumen nanti menunjuk ID field dan poin; ID yang sama membuat dokumen tetap tersambung lintas versi (R-TPL-02, R-TPL-04) |
| Hanya waktu terbit yang disimpan di baris versi; siapa yang menerbitkan ada di audit log | Audit log sudah mencatat pelaku dan tidak bisa diubah, jadi tidak perlu dua sumber |
| Nama format template tetap bisa diganti setelah versinya terbit | Nama milik template, bukan milik versi, dan hanya tampilan |
| Tabel audit log dimasukkan ke kartu | Tabel yang lebih lebar dari layar tablet menggeser halaman ke samping (D-128) |

## 5. Asumsi

- Versi kosong boleh diterbitkan. Tidak ada aturan yang melarangnya, jadi tidak saya tambahkan syarat.
- Penerbit boleh orang yang sama dengan penyusun draft. Aturan dua orang hanya diputuskan untuk form set dan tabel AP (D-139), belum untuk template biasa. Lihat E-87.
- Migrasi berikutnya yang perlu mengisi kolom baru pada versi terbit harus mematikan trigger dengan sengaja; caranya ditulis di kepala migrasi 00016.

## 6. Temuan desain baru

- **E-87** (Terbuka): apakah menerbitkan template butuh orang kedua, seperti form set (D-139).
- **Diperbaiki, bukan temuan:** halaman audit log bergeser ke samping di lebar tablet; tur otomatis menunggu halaman yang salah saat pindah dari Processes ke Process templates.
